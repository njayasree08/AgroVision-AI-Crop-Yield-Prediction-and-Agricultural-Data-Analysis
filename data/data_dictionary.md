# Data Dictionary - `agricultural_data.csv`

> **All values are SYNTHETIC.** They were generated by `src/data_generator.py` with a fixed random seed (42) using
> simplified agronomic rules. They are not field measurements and must not be used for real farming decisions.

700 records, 17 columns. Run `python generate_data.py` to regenerate the identical file.

## Derived column (created by the application, not stored in the CSV)

| Column | Type | Definition |
|--------|------|------------|
| `Yield_Category` | categorical (Low / Medium / High) | Cut-offs are the 33.3rd and 66.7th percentiles of `Crop_Yield`: **Low** < t1, **Medium** t1 <= yield < t2, **High** >= t2. Thresholds are computed once from the cleaned data, shown in the app and stored with the saved models. Result: three near-equal classes. |

## Built-in data-quality issues (intentional, to demonstrate cleaning)

* About 1-2.5 % missing values in `Soil_pH`, `Potassium`, `Nitrogen`, `Fertilizer_Usage`, `Previous_Year_Yield`, `Irrigation_Type` (never in `Crop_Yield`).
* Inconsistent spelling in some `Crop_Type`, `Season`, `Soil_Type`, `Irrigation_Type` values (case, extra spaces).
* A few physically impossible values (rainfall > 3000 mm, fertiliser or nitrogen > 600 kg/ha) that are set to missing and imputed.

## How yield is generated (summary)

Yield = crop potential x rainfall+irrigation water factor x temperature factor x pH factor x soil suitability x
nutrient (N, P, K) saturation x fertiliser response with diminishing returns and over-application penalty x
irrigation efficiency x small farm-size term x random noise (about 9 %). `Previous_Year_Yield` uses the same
farm conditions with independent noise, so it is informative but not a copy of the target.

## Leakage rules

`Crop_Yield`, `Yield_Category` and `Record_ID` are never model inputs. `State` and `District` are excluded to keep the
input form simple and avoid identifier-like high-cardinality features.
